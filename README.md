# Silkscreen enclosures

> [!IMPORTANT]
> **AI-assisted work. This is not the official Silkscreen enclosure.**
>
> These cases were designed with substantial AI assistance: the CAD is generated by code written with AI tools. They
> serve only as a baseline printable enclosure for the Silkscreen, a functional base for this early stage while the
> PCBA becomes established. They are not the "official" Silkscreen enclosure by any means. Community efforts are
> ongoing to produce a human-built case in a human-operated CAD program.
>
> See Silkscreen's AI disclosure: https://silkscreenreader.com/ai

**The 3D-printed cases for the [Silkscreen](https://github.com/iandchasse/silkscreen-pcb) e-reader**: a 4.26″ case
([`enclosures/case-426`](enclosures/case-426)) and a 3.68″ case ([`enclosures/case-368`](enclosures/case-368)). They
are modelled in CadQuery, checked as they will be printed (the checks read the sliced G-code back), and sliced for
OrcaSlicer. One repo, one folder per size.

**Status.** Both cases are at **Rev L**: bell-crank bottom keys on a 1.75 mm filament rod, held by a printed side
gate. The author has printed the standard build of each size (the 4.26″ with bottom keys and all four side keys, and
the 3.68″) from Elegoo Centauri Carbon 2 plate files of the same parts. The chinless case, the key-pair
layouts and the `-nodev` variants share its parts but have not been printed themselves. The lid and tub changes made
since 2026-10-19 are not printed yet. The OrcaSlicer projects below (the generic projects and the two plate files in
[`print/`](print/)) were written with OrcaSlicer 2.4.0-dev, checked by slicing them with OrcaSlicer 2.4's command line and
reading the G-code back, and opened in the 2.4.0-dev GUI; the generic files themselves have not been printed.

**OrcaSlicer versions.** Files written before 2026-10-21 crashed OrcaSlicer 2.3.2 and later (2.4.x, 2.5.0-alpha) as soon
as they were opened: OrcaSlicer reads the project's `filament_colour` without checking that it is there, and the files
did not have one (Bambu Studio 02.08 has fixed the same line, so the files opened there). The files now hold every
setting key OrcaSlicer itself writes, `filament_colour` among them, so they open. If an older copy of a file crashes
OrcaSlicer for you, take the current one. OrcaSlicer 2.3.1 and older are not tested.

## Print a case

**The print file is meant to come from the case step of the builder at [silkscreenreader.com/builder](https://silkscreenreader.com/builder).**
It is to hand you one OrcaSlicer project (`.3mf`) for your options, named by its configuration:
`standard-rightkeys.3mf` for a 4.26″ with bottom keys and the right pair of side keys, `368-standard.3mf` for the
3.68″ (that is the site's name for it; a build writes it as `standard.3mf` in `enclosures/case-368/out/configs/`). The
files are the generic projects that [`make_plates.py configs`](enclosures/make_plates.py) writes into each case's
`out/configs/` (build outputs, not in git).

**If the builder does not offer the file yet** (as of 2026-10-21 the site has not been updated to serve them), make it
yourself: set up the build as in [Building from source](#building-from-source) and build the case. On the 4.26″,
`src/pipeline.py --builds standard-rightkeys` (any slug from the table below) builds that one configuration and writes
`out/configs/standard-rightkeys.3mf`; once the case is built, `python -B make_plates.py configs --builds standard-rightkeys`
from `enclosures/` writes just the project again. For the 3.68″, `python -B make_plates.py configs --size 368` writes
`enclosures/case-368/out/configs/standard.3mf`. The project lands in that case's `out/configs/`. Or print from the
[plate files](print/README.md) in this repo, which are the same generic projects with the standard and chinless builds
laid out on a few plates.

**Use OrcaSlicer.** Open the project, pick your printer, and keep a **0.4 mm nozzle and 0.2 mm layers** (first layer
0.2 too). The keys are exactly 50 layers long, and the raft's air gap and the lid supports' gap are one layer each.
PrusaSlicer, Cura and the others do not read the per-part settings and are not supported. The projects were written with
OrcaSlicer 2.4.0-dev and should open in OrcaSlicer 2.3.2 and later (checked in the 2.4.0-dev GUI; 2.4.2 loads them the same way by its source; see the status above).

### What every project contains

- **Presets:** Generic Marlin Printer (0.4 nozzle), 0.20mm Standard, Generic PLA. Every OrcaSlicer install has them.
- **Bed:** the plate layout fits a 220 × 210 mm bed (an Ender-3 class printer, a Prusa MK4, a Bambu X1/P1/A1 but not the A1 mini, or larger).
- **Project settings:** no brim, and a one-loop skirt (1 layer, 3 mm away). The job starts on the skirt; peel it off.
  Global supports are off. Everything else is the generic preset (3 walls, 15 % crosshatch infill, 4 top and 3 bottom
  layers, aligned seam).
- **Settings that ride on the parts,** so changing the printer keeps them:
  - the bottom keys and the cranks sit on a **2-layer raft**, with elephant-foot compensation 0; the cranks also use
    Arachne walls;
  - the gates have elephant-foot compensation 0;
  - the lid has manual supports, build plate only, inside one enforcer per side key, the power key included
    (5 on a four-key layout, 3 on a two-key layout and on the 3.68). Nothing else is supported.
- If OrcaSlicer asks on a printer change whether to keep the project's changed settings, keep them. Do not switch on
  automatic supports.
- **Plates:** plate 1 is the case. A case with bottom keys also has plate 2, four `crank-M` cranks, which you print
  **only for APEM MJTP1117 switches** and use in place of the `crank-T` cranks on plate 1. Boards with SHOU HAN TS365ZJ
  switches, which is every JLCPCB-assembled board, use `crank-T`. There are no test prints in the projects.

### The 4.26″ configurations (16 files)

All 16 are for the touch panel **GDEQ0426T82-FT01C** (touch and frontlight) on the full Silkscreen board. The file name
is the choice you make in the builder:

|---|---|---|---|---|
| All four | `standard` | `standard-nodev` | `chinless` | `chinless-nodev` |
| Left pair | `standard-leftkeys` | `standard-leftkeys-nodev` | `chinless-leftkeys` | `chinless-leftkeys-nodev` |
| Right pair | `standard-rightkeys` | `standard-rightkeys-nodev` | `chinless-rightkeys` | `chinless-rightkeys-nodev` |
| Upper pair | `standard-upperkeys` | `standard-upperkeys-nodev` | `chinless-upperkeys` | `chinless-upperkeys-nodev` |
| **Plate 1** | 41.2–41.6 g, 3 h 19–23 min | same | 32.8–33.1 g, 2 h 26–30 min | same |
| **Plate 2** | 4 `crank-M`: 0.8 g, 7 min | same | none | none |
| **File size** | 1.23–1.25 MB | same | 0.85–0.87 MB | same |

Weights and times are OrcaSlicer's estimates with the generic presets; your printer's times will differ. The exact
figure for every file is in the table under the list below.

- **Bottom keys** (`standard`): four bell-crank keys under the screen, for the board's Back, OK, Left and Right buttons (SW9, SW8, SW3, SW2). The case is
  68.2 × 125.0 × 12.7 mm. Plate 1 holds the tub, the lid, the midplate, 4 keys (`key-426`), 4 `crank-T`, 2 gates (one
  is a spare) and the rod jig: 14 objects.
- **Chinless:** no bottom keys; touch does OK and Back. The case is 68.2 × 117.4 × 12.7 mm. Plate 1 holds the tub, the
  lid and the midplate: 3 objects. **The board must not have the four bottom-row buttons (SW9, SW8, SW3, SW2):** they hang 1.9 mm past its bottom
  edge into the chin wall. Keep R4 (their 10 kΩ pull-up).
- **Side keys,** as you hold the reader with the screen toward you: the left pair is the upper and lower keys on the
  left edge (SW7, SW5), the right pair the upper and lower keys on the right edge (SW4, SW1), and the upper pair the top
  key on each side (SW7, SW4). The power button (SW10, top of the right edge) is on every case. A key left out is plain wall; its switch may stay on the board.
- **No dev header** (`-nodev`): no opening for the dev header, the board's 12-pin expansion header (labelled J6).
  **The board must not have it fitted** (the lid's lip runs through it), so no clip-on light attachment. With the
  opening, a board with or without the header fits.
- A fully populated board fits every bottom-key case with the dev-header opening.

### The 3.68″ (1 file)

`368-standard.3mf` (`standard.3mf` in `case-368/out/configs/` when you build it), 1.08 MB: the bare x3 3.68″ 528 × 792 panel, bottom keys, three side keys, no dev-header opening.

| | |
|---|---|
| Case | 68.2 × 108.0 × 12.9 mm (14.4 mm over the keys) |
| Plate 1 | tub, lid (3 side keys, 3 enforcers), midplate, 4 `key-x3std`, 4 `crank-T`, 2 gates (one is a spare), rod jig: 14 objects, 35.50 g, 3 h 14 min |
| Plate 2 | 4 `crank-M`, for APEM MJTP1117 boards only: 0.84 g, 7 min |
| Board | the trimmed x3 board (cut at KiCad y 62; see [silkscreen-pcb](https://github.com/iandchasse/silkscreen-pcb); boards made before its Rev 1.01 need two bodge wires). **No left lower page key** (leave SW5 off: a post stands where its key would be). The top key on the left edge (SW7) is the power key: fit R72 and R74, leave off R36 and R73. Side keys: the upper key on the left (SW7), and the upper and lower keys on the right (SW4, SW1). |
| Screws | 4 × M2 × 8 socket head cap (ISO 4762); a pan head also fits; never M2 × 10 |
| Battery | 503035 up to 5.3 mm thick with up to two layers of tape on each face. Push it right, then down until it stops under the lip; tape it. Check where its lead leaves the cell, and its polarity at the board's battery connector (J5). The lead route is in [`case-368/README.md`](enclosures/case-368/README.md), "The battery". |

### You also need

- **Screws:** 4.26″, three M2 × 10 socket head cap (ISO 4762); a pan head (ISO 7045) also fits. The heads sit flush
  with the back or below it. 3.68″, four M2 × 8 (above).
- **A rod** (bottom-key cases only; not printed): 63.25 mm of 1.75 mm PLA filament, straightened and cut in the rod
  jig that is on plate 1. The steps are in [`print/4.26/ROD.txt`](print/4.26/ROD.txt) and
  [`print/3.68/ROD.txt`](print/3.68/ROD.txt).
- **The gate coupon,** once per printer and filament (bottom-key cases): [`print/4.26/coupon-gate.stl`](print/4.26/coupon-gate.stl)
  or [`print/3.68/coupon-gate-x3std.stl`](print/3.68/coupon-gate-x3std.stl), or the "Test prints" plate of the plate file.
- **A battery:** a 503035 LiPo, 500 mAh, with a protection board and a JST PH 2.0 2-pin connector. The polarity is not
  standard, so meter it against the + pin of the board's battery connector (J5) before the first plug-in. On the 4.26″, wind the spare lead round the midplate's
  cleats.
- **Assembly:** lay the tub face down on a cloth until the board is in. [`print/README.md`](print/README.md) has the
  steps.

## The `print/` folder

[`print/`](print/) holds the author's own files and every part on its own. Start at [`print/README.md`](print/README.md),
which also lists what to reprint after each design change.

- [`silkscreen-426-plates.3mf`](print/silkscreen-426-plates.3mf) (3.3 MB) and
  [`silkscreen-368-plates.3mf`](print/silkscreen-368-plates.3mf) (2.1 MB): OrcaSlicer projects with the released builds
  laid out, in the same generic setup as the generic projects (Generic Marlin Printer 0.4 nozzle, 0.20mm Standard,
  Generic PLA; every plate fits a 220 × 210 mm bed; they should open in OrcaSlicer 2.3.2 and later (checked in the 2.4.0-dev GUI; 2.4.2 loads them the same way by its source); pick your own printer
  and filament). The 4.26 file has four plates: 1 the standard case (with the rod jig), 2 the 4 `crank-M` only for APEM
  MJTP1117 boards, 3 the chinless case, 4 test prints (a PCBA test-fit dummy, the chin coupon with a key, the gate coupon
  with a gate). The 3.68 file has three: 1 the case, 2 the 4 `crank-M`, 3 test prints. The light-strip builds are not in
  them.
- [`print/4.26/`](print/4.26/) and [`print/3.68/`](print/3.68/): every part on its own, `<part>.stl` in print pose and
  `<part>.step` in the CAD frame, plus `ROD.txt`. A loose STL needs the per-part settings above set by hand.
- [`print/rod-jig.stl`](print/rod-jig.stl) and `.step`: the jig that straightens and cuts the filament rod.

The per-configuration projects are not in `print/`: they are build outputs, meant to be served by the website. To make
your own copies, or Elegoo CC2 versions of them (`--printer cc2`), run `make_plates.py configs`
([Building](#building-from-source)).

The author prints on an Elegoo Centauri Carbon 2 from plate files of the same parts with the CC2's own presets, every
build included (the light-strip ones too). `python -B make_plates.py --printer cc2` writes them to `print/cc2-local/`
(not in git), if you have a CC2 and want them.

## In development: the light-strip cases

Each project can also build a case for the
[Silkscreen light strip](https://github.com/iandchasse/silkscreen-light-strip), a flex PCB frontlight that plugs into the board's
frontlight connector: the 4.26″ has 16 such configurations, the 3.68″ one build. **These cases are in development and are not released.**
The strip is rev A and untested, and the website does not offer its cases. The builds exist in the source and in plates
2 and 5 of the author's CC2 plate files (`print/cc2-local/`, not in git), but nothing here asks you to print them.

## Building from source

- **Python 3.11:** one virtual environment per case, made from that case's `requirements.txt` (CadQuery 2.8, trimesh,
  ezdxf, manifold3d, shapely, scipy, matplotlib and others). Either environment can run the shared scripts.
- **OrcaSlicer 2.4** at its default install path, for the slicing read-backs and the per-configuration projects. Its
  command line also makes `enclosures/orca-project-defaults.json` (the settings OrcaSlicer fills in for a project;
  `python -B make_plates.py defaults`, only needed after an OrcaSlicer update), which the plate files and projects are
  written over.
- **KiCad 9** only for `src/prepare_hardware.py`, which re-derives the board files in `hardware/` from a
  silkscreen-pcb checkout. The derived files are already in `hardware/`, so you do not need KiCad to build.
- Run every script with `python -B`. Outputs go to each project's `out/`, which is not in git.

The 4.26″, from `enclosures/case-426`: `src/pipeline.py` builds all 32 configurations and runs their checks (about an
hour from nothing, and cached after). It also runs `make_plates.py` (the plate files), `make_plates.py configs` (one
generic project per configuration) and `src/configs_slice.py` (which slices and checks them) itself, so nothing else is
needed. To redo just those three after a build, run `make_plates.py` and `make_plates.py configs` from `enclosures/`,
then `src/configs_slice.py` from `case-426`.

The 3.68″, from `enclosures/case-368`: `src/build.py`, then for each of the two builds `mechanics.py`, `dummy.py`,
`plates.py`, `slice_check.py` and `lid_close.py`; then, from `enclosures/`, `make_plates.py` and
`make_plates.py configs --size 368`, and `case-426/src/configs_slice.py --size 368`.

The full commands and options are in [`enclosures/README.md`](enclosures/README.md#rebuilding).

## Checks

The point of the checks is that parts fit as printed, so most read the sliced G-code, not the CAD. Each case's README has
a section on them.

- Parts that should be shared between builds are identical (`out/shared-parts.json`), and each of the 32 4.26″
  configurations matches its twins.
- `asprinted.py`: where the lid sits when pressed home, every screw's thread and tip, latch play, and the lid against
  the midplate.
- `lid_close.py`: the latch arms on the way in.
- `slice_check.py`: the as-printed read-back, the detents and the cranks' swing.
- `configs_slice.py`: every generic project, for key layers, side-key bases, supports only inside the enforcers, and a
  job that starts on the skirt.
- 3.68″ only, `bayread.py`: the battery bay and the mid-plane ties.
- `mechanics.py`: key forces and travel.

A few vendor reference files (the panel drawings and the switch datasheets) are not in this repo; each case's
`hardware/reference/SOURCES.md` says where to get them. The builds do not need them.
